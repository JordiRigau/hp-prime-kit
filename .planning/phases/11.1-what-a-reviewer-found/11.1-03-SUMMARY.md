# Plan 03 summary: the same probes on the Virtual Calculator

## Why

The reply on the forum promises the probes of plans 01 and 02 on the emulator as
well as on the G2. Until now none of them had been run there.

## How it was run

On the Virtual Calculator 2.4, build 2025-09-15 (`HPPrime.exe` 2.4 r15515), on
2026-11-07, with `hpprime examples --compile`: each batch on `Prime_1`, reset before
it, with the Function app active and `Entry` at 0. **Both controls, `ZCOK` and
`ZCBAD`, came out right in all four batches**, so every answer is stored: 163 rows in
`docs/commands/results.tsv`, each program's compile answer under its fact, and what
each one answered through `--probe` calls `EXPR("NAME")` in `HPKDOC`.

- **The programs are the G2's, unchanged**, in four batch files in
  `probes/emulator-2026-11/`, each program headed by its fact, and with its `--probe`
  lines. A batch leaves every program on the calculator, where the G2 had one
  replacing the other under `ZQTEST`. So programs that export the same names are in
  different batches: `F` (RFA, RFB, RFN), `ZV1` onwards (E6, E7, E8, RXO), `ZHOK` (H3,
  H5). Where the order matters, the batch keeps it: E9 before E6, RXN before E7,
  P5lib before P5, RNAlib before RNA, ROA before ROBlib, and ROBlib before ROC in a
  run of its own.
- **Not run:** C1 to C3 and RC1 to RC3, since the tool's own controls stand in for
  them; H2, whose function H5 holds; M2, replaced by M4 on the G2 the same day;
  ROAlib, a filler; STUBA and STUBB, the stubs left on the G2. RNBlib, the library
  sent again, cannot be put into an emulator that is running, so `Check` was pressed
  again on the library instead. That is not the same thing, and the table says so.
- **Who pressed the keys.** Jordi asked, on 2026-11-07, for the clicks to be done by
  the agent. A script in the session's scratchpad posted messages to the `Prime_1` window
  only: clicks on the soft keys and on the picture of the calculator's keys, arrows,
  `Esc` and `Enter` as key messages, and names as characters. Jordi's mouse and
  keyboard were not used. The script read a capture of the window before every key,
  telling the catalogue, the editor and a message apart by the soft-key row, and the
  selected program by its name against the list read once, and it stopped at the
  first screen that was not the one expected. The answers on Home were read from the
  same captures.
- **Two traps on the way.** In this calculator's state the Program Catalogue is
  sorted by date, so an edited program moves to the top, and after leaving the editor
  the selection returns to the second row. A first pass that relied on counting
  `Down` checked `ZCBAD` twenty times over and left batch A's programs unchecked.
  `ZCBAD` fails anyway, so this was harmless, and the editors' titles gave it away.
  Batch A was then done with the list sorted alphabetically (`Más`, `Orden.`,
  `Alfabéticamente`), the selected name read before each `Editar`. It is a likely
  reason why the person lost the order in 08.1-04.
- **ROBlib is in batches C and D**, so batch D needed `--replace` for that one row,
  which the tool refuses otherwise. It answered the same. The tool then wrote that
  row twice, see *What is left*.
- The screens are in `programs/_emulator-review-2026-11-07/`, which git ignores: every
  step of every `Check`, one picture per batch of each program's title and answer, and
  the Home tests.

## What differed, and what settled it

**`ppl.global-namespace`: which of two programs exporting one name answers.** On the
G2, sent `ZQLIB` and then `ZQTEST`, the older answered, until it was sent again. On the
emulator, copied as files and compiled with `Check` in the same order, the one compiled
last answered, and it changed back when `Check` was pressed again on the other. Both
compile in both. The routes differed, arrival over USB against `Check` on a copied
file, so two runs could tell the firmware from the route: on the emulator, send the
two programs through the Connectivity Kit, so that they arrive as on the G2; or on the
G2, press `Check` on the older one in its editor. Jordi chose the first.

**It is the route.** Sent through the Kit, the emulator answered as the G2 did: 5321,
and 5322 once `ZQLIB` was sent again, with `ZRCLT` 5323 and the new `ZRCLU` 5324
showing that each arrived compiled. The fact now says both: sent, the one there
longest answers (G2 and emulator); compiled with `Check`, the one compiled last
(emulator). `Check` on a G2 was not tried.

How it was run, the second time. The first emulator window always opens `Prime`, and
with two windows open the Kit listed one calculator without saying which. So, with
everything closed and Jordi's approval, Jordi's `Prime` folder was moved into the kit's
`set-aside` folder, with a SHA-1 list of its 95 files. A copy of the kit's clean
`Prime_1` snapshot took its place, and one window opened it with no program on it. The
Kit then saw one calculator, which could only be that one. `ZQLIB.hpprgm`, built from
`probes/RNAlib.txt`, and `ZQTEST.hpprgm`, from `RNA.txt`, went into the Kit's content
library (`Contenido`). Each was sent with a posted right-click on its row, a capture of
the menu, and a posted click on `Enviar`. Each arrived in the calculator's folder 96
or 184 bytes longer, its compiled block. `ZQLIB.hpprgm` was then replaced by the build
of `RNBlib.txt` and sent the same way. The calculator replaced its `ZQLIB` with no
question asked. The answers were typed on Home and read from captures, which are in
`programs/_emulator-review-2026-11-07/kit/`. Afterwards the Kit and the emulator were
closed with close requests, and the test files left the library. The throwaway went
to `set-aside`, and Jordi's `Prime` came back, its 95 files identical by SHA-1.

The first try, earlier the same day, stopped before anything was sent. With `Prime`
and a reset `Prime_1` open, a posted double-click on `Programas` in the Kit's tree, to
find out which calculator it listed, made the Kit crash (`APPCRASH`, `0xc0000005` in
`ConnectivityKit.exe` 2.4.0.15515). On every connection the Kit empties the mirror
folder of a calculator with that name down to the built-in apps, and it did so to
`HP Prime` and `MyCalc`. `HP Prime` is the G2's mirror. It comes back when the G2 is
connected and its tree expanded, and `programs/_g2-backup-2026-11-04/` holds a copy
from the day before the USB sends.

## What changed

- **Facts, in `docs/topics/ppl.md`.** These state the emulator's answer beside the
  G2's, with the date: `ppl.local-limit`, `ppl.local-block-scope`, `ppl.index-call`,
  `ppl.export-initialised`, `ppl.export-home-variable`, `ppl.no-end-keywords`,
  `ppl.locals-at-top`, `ppl.home-no-parentheses`, `ppl.call-no-parentheses`,
  `ppl.getkey-no-parentheses`, `ppl.matrices-by-value`, `ppl.expr-empty`,
  `ppl.expr-dynamic-access` and `ppl.compilation-order`. `ppl.global-namespace` says
  which program answers by the route: sent, the older (G2 and emulator); compiled with
  `Check`, the last compiled (emulator). `ppl.return-in-loop`, `ppl.letter-digit-names` and
  `ppl.local-m-matrices` gain a program of their own, run on the emulator only, and
  say so.
- **New statements, labelled `emulator`**: `F(2)` typed on Home is a syntax error, and
  `EXPR` reads `F` and `F()` as the variable (`ppl.export-home-variable`). `TICKS()` is
  a syntax error at 1 and a number at 2 (`ppl.home-no-parentheses`, and the `TICKS`
  entry). The pair typed as two characters is refused at 0 and 1. The
  `unverified` line that said the Virtual Calculator had not been tried now names only
  what is still untried, another firmware.
- **Entries.** `Entry` says *G2 and emulator* for `MYFUNC()`. `TICKS` says what it
  answers at 1 and 2. The group pages were regenerated with `hpprime docs`.
  `docs/llms.txt` did not change, since no fact's first sentence did.
- **`docs/commands/results.tsv`**: 163 rows, all dated 2026-11-07, Virtual Calculator
  2.4, build 2025-09-15.
- **No tool changed.** The scripts that pressed keys and read the screen stayed out of
  the repository.

## What is left

  `ppl.global-namespace` is the emulator's alone.
- **`results.tsv` got one row twice.** `write_results` keys a new row by its raw call,
  and a stored one by the cleaned call (`\n` written as `\\n`), so a compile row
  measured again is appended rather than replaced. The duplicate was removed by
  rewriting the file with the tool's own writer, which dropped exactly that line. This
  and `test_usb.py` on stock Windows went to a separate session. Its fixes are in the
  same folder, uncommitted, and are not part of this plan.
- **MAKEMAT**: `ZMSIZ` answered {1, 1, 0, 0} on both, so 150x150 and 200x200 were
  refused with a 100x100 held. Whether that now goes into the documentation is
  Jordi's call.
- **Pressing `Check` for a person.** This run shows the emulator's catalogue, editor
  and Home can be driven with posted messages and checked against captures.
  `AGENTS.md` §7 and `docs/tools.md` still say somebody presses the keys. Whether

  hand, the steps printed in `tools.md` do not mention the date sort.
